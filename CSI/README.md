# 📡 مشروع WiFi CSI Sensing — كشف الأشخاص بالواي فاي

نظام بيستخدم **إشارات الواي فاي (CSI)** عشان يكشف وجود شخص في الأوضة، مكانه (يمين/
شمال/نص)، وإذا كان بيتحرك، وبيعرض ده كـ **heatmap + نقطة بتتحرك** على الشاشة بـ OpenCV.

- **2× ESP32 DevKit v1** (اللي معاك) + **راوتر (Access Point)**.
- الكود كله جاهز. إنت مطالب بس: تحرق الفيرموير مرة واحدة على الـ ESP32، وبعدين تضغط
  على `run.bat` وتشوف النتيجة.

---

## 🧭 إزاي النظام شغال (باختصار)

```
   [Router/AP]  <---- ping / CSI reply ---->  [ESP32-L]  و  [ESP32-R]
                                                    \           /
                                                     \         /
                                                      USB serial
                                                         |
                                                   [الكمبيوتر]
                                                         |
                                  قارئ سيريال -> معالجة -> OpenCV (heatmap + نقطة)
```

1. كل ESP32 بيبعت ping للراوتر، والراوتر بيرد، والـ ESP32 بيطلع الـ **CSI** بتاع القناة
   اللاسلكية (قوة الإشارة لكل subcarrier).
2. لما شخص يتحرك قدام الـ ESP32، **القناة بتتلخبط** — الـ amplitude بتاع الـ subcarriers
   بيتذبذب والـ RSSI بينزل.
3. البرنامج بيقيس التذبذب ده لكل جهاز، ومن الفرق بين الجهازين بيقدّر الشخص **يمين ولا شمال**.
4. كل ده بيتعرض على خريطة الأوضة كنقطة متحركة فوق heatmap.

## 🔧 التشغيل الحقيقي (بالـ ESP32)

### الخطوة 1 — حرق الفيرموير (مرة واحدة)

اتبع خطوات ملف [firmware/README.md](firmware/README.md) بالظبط:

1. من ESP-IDF Terminal: `cd firmware\csi_recv_router`
2. `idf.py set-target esp32`
3. `idf.py menuconfig` → سجّل اسم شبكة الراوتر والباسوورد
4. `idf.py build`
5. `idf.py -p COM3 flash` (لأول ESP32) و `idf.py -p COM4 flash` (للتاني)

> الاثنين بيتحرق عليهم **نفس الكود**.

### الخطوة 2 — رتّب الأجهزة في الأوضة

- حط **الراوتر** في مكان ثابت.
- حط **ESP32-L** على شمال الأوضة و **ESP32-R** على يمينها (نفس المستوى تقريبًا،
  وبيتجهوا تجاه منطقة الحركة).
- خلّي بين كل ESP32 والراوتر مسافة كويسة (أكتر من متر).

### الخطوة 3 — اضبط المنافذ (الـ COM ports)

افتح ملف [config.json](config.json) وعدّل سطور `port`:

```json
"devices": [
  { "id": "left",  "label": "ESP-L (left)",  "port": "COM3", "x": 0.15, "y": 0.5 },
  { "id": "right", "label": "ESP-R (right)", "port": "COM4", "x": 0.85, "y": 0.5 }
]
```

- `x` و `y` = مكان الجهاز في الأوضة (نِسَب من 0 لـ 1: `x=0` يسار، `x=1` يمين،
  `y=0` فوق/قريب من الراوتر، `y=1` تحت/بعيد).

> عشان تعرف أسماء المنافذ عندك، شغّل: `python src\main.py --list-ports`

### الخطوة 4 — شغّل

دبل كليك على:

```
run.bat
```

هيجهّز بيئة بايثون ويثبّت المكتبات ويشغّل البرنامج.

## 🖥️ إيه اللي هتشوفه في الشباك

- **خريطة الأوضة** (من فوق) فيها الراوتر والـ ESP32.
- **Heatmap** متراكمة بتوضح أماكن الحركة (أحمر = حركة كتير) — بتنظّفها OpenCV
  (GaussianBlur → threshold → morphology → contours) فبتطلع **شكل نضيف** لكل منطقة
  حركة بدل نقطة مشوّشة.
- **نقطة خضرا** هي الشخص (منعّمة بفلتر Kalman فبتتحرك بثبات من غير ترعيش)، وبتسيب
  **أثر (trail)** وراها.
- **Contours صفرا** حوالين كل منطقة وجود (blob) الـ OpenCV لقطها، مع لابيل P1, P2…
- **لوحة HUD** فيها:
  - `PRESENCE` — في حد ولا لأ
  - `STATE` — MOVING / IDLE
  - `POSITION` — LEFT / CENTER / RIGHT
  - `X` — مكانه يمين/شمال (0..1)
  - `PEOPLE` — عدد الـ blobs اللي OpenCV لقطها (تقدير عدد الأشخاص)
  - نشاط و RSSI لكل جهاز

### الأزرار في الشباك

| الزر | الوظيفة |
|---|---|
| `q` | إغلاق |
| `r` | عرض/إخفاء الـ CSI الخام (amplitude) |
| `c` | إعادة معايرة الخلفية (سيب الأوضة فاضية وقتها) |
| `h` | مسح الـ heatmap |

## ⚙️ إعدادات مهمة في config.json

في قسم `processing`:

| الإعداد | المعنى |
|---|---|
| `calibration_seconds` | مدة معايرة "الأوضة الفاضية" أول ما يشتغل (سيبه فاضي في الوقت ده) |
| `motion_threshold` | حساسية كشف الحركة (علّيها لو حساس زيادة، واطيها لو مش بيلتقط) |
| `activity_scale` | مقياس تطبيع النشاط |
| `rssi_weight` | وزن تأثير هبوط الـ RSSI في التقدير |
| `smoothing_alpha` | نعومة حركة النقطة (أكبر = أسرع استجابة، أصغر = أثبت) |
| `count_thresholds` | عتبات تقدير عدد الأشخاص |
| `blob_threshold` | عتبة الـ OpenCV لفصل مناطق الحركة (علّيها لو بتطلع مناطق زيادة) |
| `blob_min_area` | أقل مساحة للـ blob عشان يتعامل كشخص (شيل الضوضاء الصغيرة) |
| `kalman_process_noise` / `kalman_measurement_noise` | توازن نعومة حركة النقطة وسرعة استجابتها |

> بعد أي تغيير في وضع الأجهزة أو الأوضة، اعمل معايرة جديدة بضغطة `c` (والأوضة فاضية).

## 🧠 إزاي بيشتغل الشكل الحراري والعدّ (OpenCV + Kalman)

بعد ما `processor.py` يطلع (وجود / اتجاه يمين-شمال / حركة)، بيحصل حاجتين جديدتين:

1. **Kalman filter** (`kalman.py`) بيمسك الـ (x, y) وبيتنبأ بالسرعة، فالنقطة بتتحرك
   **بثبات وبلا تأخير** لما الشخص يتحرك (اللايف الحقيقي).
2. **Occupancy engine** (`occupancy.py`) بيراكم المواضع في خريطة حرارية 2D، وبعدين
   بـ OpenCV بيعمل: `GaussianBlur → threshold → morphology(open/close) → findContours`.
   كل contour بيمثل **منطقة وجود** (شخص):
   - **contour** = الشكل الحراري بتاعه (بيترسم على الخريطة)
   - **centroid** = موقعه المكرَّر
   - **عدد الـ contours** = تقدير عدد الأشخاص

> ⚠️ **بصراحة:** مع جهازين ESP32 (رابطتين واي فاي بس) بنقدّر اليمين/الشمال بدقة كويسة،
> بس **شخصين واقفين قريبين في العمق مش بيبانوا منفصلين**. عشان تحديد 2D حقيقي وعدّ
> دقيق لأكتر من شخص، محتاج **3–4 أجهزة** (روابط أكتر) أو موديل ML متدرّب — وده الجزء
> "الأدفانسد" اللي ممكن نبنيه فوق الكود ده من غير ما نغيّر الهيكل.

---

## ⚠️ نقط مهمة وصريحة (عشان متتفاجئش)

1. **ده كشف حركة أساسًا.** النظام بيلتقط إن الشخص بيتحرك. الكشف عن شخص **واقف ساكن
   تمامًا** ده مستوى متقدم (محتاج ML ومعايرة أطول).
2. **اتجاه يمين/شمال دقيق**، لكن **العمق (قريب/بعيد)** تقدير تقريبي — التحديد ثنائي
   الأبعاد الحقيقي محتاج عدد أجهزة/روابط أكتر (مرحلة متقدمة).
3. **عدّ الأشخاص** بيشتغل دلوقتي بطريقتين: تقدير نشاط (thresholds) + **عدّ الـ blobs**
   اللي OpenCV بيطلعها من الـ heatmap. الاثنين **تقدير** — العدّ الدقيق لمجموعة أشخاص
   واقفين جنب بعض محتاج بيانات تدريب + موديل ML (Random Forest / XGBoost)، وده موجود
   في خطة الفريق (Member 4).
4. **النتيجة بتتأثر بالبيئة** — الأثاث، الجدران، أشخاص تانيين في البيت، أجهزة وايفاي
   تانية. عشان أفضل نتيجة، جرّب في بيئة هادية الأول.
5. **الـ heatmap والخريطة رسم تقريبي** مش مقياس هندسي دقيق — الغرض تصويري وتفاعلي.

## 🐞 استكشاف المشاكل

| المشكلة | الحل |
|---|---|
| `cannot open COM3` | تأكد إن الـ ESP32 موصول والدرايفر متثبت، وجرّب `--list-ports` |
| الشباك مش ظاهر | تأكد إن `opencv-python` اتثبت. جرّب `python -m pip install opencv-python` |
| مفيش سطور CSI في الـ monitor | تأكد إن الراوتر 2.4GHz، واسم الشبكة/الباسوورد صح، والـ ESP32 واخد IP |
| النقطة بتترعش أوي | زوّد `smoothing_alpha` أو قلل الحساسية |
| مش بيلتقط الحركة خالص | قلل `motion_threshold` أو اعمل معايرة (`c`) والأوضة فاضية |
| بيانات ناقصة / تعليق | قلل `CONFIG_SEND_FREQUENCY` في الفيرموير إلى 50 وأعد الحرق |

## 🚀 الخطوات الجاية (Advanced)

- **عدّ الأشخاص بدقة**: جمع بيانات + تدريب مصنّف (SVM/Random Forest أو CNN على spectrogram).

- **كشف الشخص الساكن**: كشف التنفس (breathing) من اهتزازات الـ CSI الدقيقة.
- **Dashboard ويب** بدل شباك OpenCV (Flask/FastAPI + بث مباشر).
